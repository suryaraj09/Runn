# Contributing to Runn

Thank you for your interest in contributing to Runn! This document provides guidelines and instructions for contributing.

## Code of Conduct

Be respectful and constructive in all interactions. We are committed to providing a welcoming and inclusive environment.

## Getting Started

1. Fork the repository
2. Clone your fork locally
3. Create a feature branch (`git checkout -b feature/your-feature`)
4. Make your changes
5. Commit your changes with clear messages
6. Push to your fork
7. Submit a Pull Request

## Reporting Issues

Before creating a bug report, check the issue list to avoid duplicates.

When reporting a bug, include:
- Clear description of the issue
- Steps to reproduce
- Expected behavior
- Actual behavior
- Your environment (OS, Python version, etc.)

## Feature Requests

Feature requests are welcome! Please include:
- Clear description of the feature
- Use case and motivation
- Possible implementation approach (if you have ideas)

## Pull Request Process

1. Update documentation if needed
2. Add tests for new functionality
3. Ensure all tests pass
4. Follow the existing code style
5. Write clear commit messages
6. Reference related issues in the PR description

## Workflow Modifications

When modifying `.github/workflows/streak.yml`:
- Test the workflow thoroughly
- Document any changes to the schedule or logic
- Update README.md if behavior changes
- Consider backward compatibility

## Questions?

Feel free to open an issue with your question or start a discussion. We're here to help!
